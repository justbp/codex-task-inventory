# M4.3 可配置 WIP 策略

状态：已实现  
日期：2026-08-09

## 目标

让看板对同时推进的工作数量提供明确边界，同时保留用户的业务判断权。策略只负责提醒或阻止新增工作，不会自动选择主线、调整优先级或结束任务。

## 产品行为

- 默认今日主线上限为 1。
- 默认后台 Run 上限为 2。
- 默认待验收上限为 2。
- `warn` 模式：展示达到或超过上限的提醒，但允许用户继续。
- `block` 模式：阻止新增今日主线或启动新的 Run；已有工作不会被取消或改写。
- 待验收达到上限时，`block` 模式阻止继续启动新 Run，促使用户先处理验收积压。

今日主线和待验收按 Work Item 统计；后台执行按 `queued`、`running` Run 统计。三者不共用状态字段。

## 数据与 API

新增：

- `wip_policy`：全局策略、执行方式和版本号。
- `wip_policy_audit_events`：修改前后版本、actor、来源 thread 和时间。
- `GET /api/wip-policy`：读取策略和当前计数快照。
- `PATCH /api/wip-policy`：用户使用 `expectedVersion` 修改策略。
- `GET /api/wip-policy/audit`：读取策略审计记录。

Work Item 启动和旧任务看板的手工启动都会经过策略检查。Work Item Run 的检查位于幂等创建事务内部，因此：

- 阻止时不会留下半创建 Run。
- 相同幂等键的安全重放不会因为之后的 WIP 数量变化而失败或重复启动。

## 页面交互

今日工作台新增 WIP 状态条：

- 展示主线、后台 Run、待验收的“当前值 / 上限”。
- 达到上限显示黄色，超过上限显示红色。
- 设置弹窗允许修改三个上限以及“仅提醒 / 阻止新增”。
- 页面明确说明策略不决定业务优先级。

## 不变量验证

- I-05：Work Item 与 Run 分别统计，没有合并状态模型。
- I-06、I-14：策略由用户配置；Codex 修改策略会被拒绝；系统不选择主线。
- I-07：WIP 策略不提供任何完成任务的路径。
- I-11、I-12：配置更新带 actor、版本和审计，旧版本返回冲突。
- I-13：Run 创建仍使用原幂等键，策略检查不会破坏重放。
