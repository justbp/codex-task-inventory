# Codex Task Monitor 产品边界

状态：Active  
日期：2026-08-10

## 产品目标

帮助同时处理多个 Codex 对话的用户快速知道：Codex 正在做什么、何时需要介入、哪些结果等待检查。

看板是 Codex 的任务监控器，不是个人工作操作系统，也不负责规划或约束 Codex 的思考过程。

## 核心路径

1. 用户用标题、可选说明和工作目录记录事项。
2. 用户把事项交给 Codex。
3. 看板根据真实 Codex 状态展示执行中、等待我、中断和待 Review。
4. 用户需要介入时回到原 Codex 对话。
5. 用户检查结果并确认完成。

## 产品不变量

### I-01：真实 Codex 状态是运行状态的事实来源

看板从 Codex 本地状态和事件读取运行情况，不自行推断或伪造执行状态。

### I-02：用户决定是否完成

用户可见任务产生可检查结果、需要行动的信息，或有实质进展后中断时进入待 Review。内部协调、静默运行和无产物中断不进入待 Review。只有用户确认，待 Review 任务才进入已完成。

### I-03：看板不扩写任务输入

启动 Codex 时只发送用户填写的标题和说明。看板不得自动补充目标、验收标准、范围、停止条件或执行计划。

### I-04：原始对话保持独立

看板只保存排布、项目、标签、优先级、备注和完成确认等本地元数据，不把对话全文复制进任务正文。

### I-05：同一结果只提醒一次

同一次有价值的完成或中断只进入一次待 Review；用户确认后不重复提醒。发生新的可检查结果、行动请求或有实质进展的中断时重新进入待 Review。

### I-06：保持简单产品边界

允许外部 Skill 在独立 Codex 对话中按需读取看板、提出建议，并在用户明确要求时调用现有接口启动子任务。看板可以展示外部 Skill 最近一次生成的、只读且可丢弃的注意力建议，但该建议不得成为任务事实、不得自动排期或约束用户，也不得引入 Work Item、Run、Context Envelope、Recovery Point、Decision Request、WIP 策略或持久化的 AI 管理系统。

管理对话和注意力建议不得成为任务事实来源；每次可以新建并重新读取紧凑看板快照。定时巡检可以读取看板并更新建议展示，但不能自动创建、启动、修改或验收任务。

## 验收标准

- 用户可以记录一个简单事项并启动 Codex。
- 执行中和等待输入的任务显示在正确位置。
- 产生可检查结果、行动请求或有实质进展的中断后进入待 Review，并可回到原对话。
- 内部委派空壳、静默 heartbeat 和无产物中断不占用待 Review。
- 用户通过后任务进入已完成；再次执行后重新进入待 Review。
- 用户无需理解任何内部任务模型即可完成上述路径。
